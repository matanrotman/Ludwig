## ⚠️ CLOUD SYNC IS DEAD — proven end-to-end 2026-07-16. The user's writing exists ONLY on this Mac.
**Do not trust AppFlowy Cloud as a backup, and don't spend time "fixing" sync — it is not fixable locally.**
- `beta.appflowy.cloud` blocks the old realtime protocol (`/ws/v1`) at its edge: **426 `{"error": "Please upgrade to latest client"}`** — for every version string (tested 0.7.9→99.0.0), any User-Agent, valid token or none, from Israel and from the US. Proven with a Rust probe using the app's **exact** stack (tokio-tungstenite 0.20.1 + native-tls, same headers): `scratchpad wsprobe` result identical to curl/python, so it's not TLS fingerprinting.
- **The official binaries are NOT built from the public source.** The user's very first run (2026-07-11 19:30, the official appflowy.com download, before any local build) logged `client_api::v2::actor` — a module that does **not exist** in the public `client-api` pin (`592f644`, May 2025) that the 0.12.5 release tag builds (verified: tag's Cargo.toml pins it exactly, no `[patch]` override). Official users run a private v2-protocol client via auto-update; that's why nobody else complains. Corroboration: server self-reports **0.17.10** while the public AppFlowy-Cloud repo tops out at **0.9.64**; public app repo has **zero** v2 glue (`grep -rn "client_api::v2\|WorkspaceController" rust-lib` = empty); GitHub issue 2026-07-02 "Stop lying and spamming that this is OSS".
- **Consequence for every source-built AppFlowy (ours included): pages are created on the cloud as EMPTY SHELLS over HTTP; typed content rides the blocked websocket and never arrives.** Final proof: doc `c4606ec3-…` (page `b7257738-…`) = **146 blocks locally** (children_map in `log.sync.2026-07-15-20`) vs **741-byte skeleton with 1 empty paragraph** fetched from the cloud (`GET /api/workspace/v1/{w}/collab/{id}?collab_type=0`, Bearer token, HTTP 200).
- Why the app never surfaced it: `client-api`'s retry loop swallows the error (`retry.rs:119` discards it unlogged; only `AuthError` stops retrying, and the 426 maps to `WSError::Http`) → silent 15s-interval reconnect forever (~4.5k attempts/day). `🟢websocket connect success` appears **zero times in every log on this machine, ever**.

## Local build quick-reference
Run from `~/Projects/AppFlowy/frontend`, with `~/flutter/bin`, `~/.cargo/bin`, `~/.pub-cache/bin` on PATH:
```
# Dev run (debug; uses the user's real data_dev* workspace):
cargo make --profile development-mac-arm64 appflowy-core-dev-macos
cargo make code_generation
cd appflowy_flutter && flutter run -d macos

# ⭐ SHIP A FIX TO THE USER'S DOCK APP (this is the one that matters):
#    rebuilds in place at exactly the path the dock icon points to.
cd appflowy_flutter && flutter build macos --debug
#    verify it took by CONTENTS — NOT by timestamp. Flutter preserves the cached
#    artifact's mtime, so a correct rebuild can legitimately show an OLD time.
KB=build/macos/Build/Products/Debug/AppFlowy.app/Contents/Frameworks/App.framework/Resources/flutter_assets/kernel_blob.bin
strings "$KB" | grep -c IntegrationTestWidgetsFlutterBinding   # want 0 (non-zero = TEST build)
strings "$KB" | grep -c runAppFlowy                            # want >0 (the real app)

# Real-target regression test (the ONLY trustworthy way to check RTL geometry):
flutter test integration_test/desktop/document/document_rtl_empty_caret_test.dart -d macos

# ⚠️ ALWAYS run BOTH of these afterwards — the test run leaves the dock app broken in
#    two independent ways, and each looks identical to "the build is broken":
flutter build macos --debug   # 1. the test run replaced the dock app with a TEST build
defaults delete com.appflowy.appflowy.flutter flutter.io.appflowy.appflowy_flutter.path_location
                              # 2. it also pointed the app at an empty test sandbox
# Then verify by CONTENTS (not timestamp — see rule 2 above for why):
KB=build/macos/Build/Products/Debug/AppFlowy.app/Contents/Frameworks/App.framework/Resources/flutter_assets/kernel_blob.bin
strings "$KB" | grep -c IntegrationTestWidgetsFlutterBinding   # want 0
strings "$KB" | grep -c runAppFlowy                            # want >0

# Release build: NOT what the user runs. It targets the data* workspace, which is
# a different (stale) cache — building it made pages look "missing". Avoid unless
# genuinely packaging a release.
```
